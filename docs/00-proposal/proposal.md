# 渐进式算子编程（POP）：面向 MegaKernel 的可执行契约与逐层下沉

## 摘要

MegaKernel 把上百个计算步骤压进一个 kernel 后，实现方案由一个高维决策向量刻画：融合划分、切分、片上缓存复用、流水同步、向量化（VF）融合边界。该向量的空间是天文数字，而**代价函数不可分解**——片上容量把不同融合组耦合在一起，CV 流水又让局部最优随全局编排改变。这意味着既不能枚举，也不能靠动态规划精确求解，只能搜索。

搜索的瓶颈不在模型能力，而在**每层的决策界是否可判定**。当前工业栈（AscTile、CANNBot-DSL）已经提供了分层表达，但层间契约是**散文式的**（文档、skill 描述、门禁清单）：不可求值、不可检查、不可剪枝。证据是官方材料对同一硬件参数的表述互相冲突（L0C 容量 128KB vs 256KB；UB 物理 256KB 而 API 返回 248KB，均待复核）。对 Agent 而言，散文契约等于没有契约——它只能靠"读代码 + 猜"。

本文提出 **POP（Progressive Operator Programming）**：不新造 IR，而是在既有三层栈之上加一层**可执行契约（executable contract）**与**下沉决策层**。每层契约写成五元组 $(\mathcal{V},\Omega,\Phi,\kappa,\mu)$：可决策的变量、可观测的视图、可检查的不变量、可求值的代价界、可比较的度量。Agent 在 Tile 层只决定融合边界与算法，把流水/分配/同步让渡给编译栈；当**当前层的剩余自由度已无法解释性能缺口**时下沉到 Buffer 层，再不行沉到 Register 层。程序形态是混合的：整体高层，局部低层。

本文的理论落点是三条可证的命题：契约可靠性（soundness）、**不可行性对精化单调**（这使"失败"可永久剪枝，是分层有效的真正理由）、以及预算化回跳的终止性。本文明确**不**主张完备性与全局最优。

预期产出：可执行契约规范与检查器、下沉决策器、结构化观测面（融合 grouping / pipeline trace / 代价界反馈）、以及在 Ascend 950PR 上相对 AscTile、CANNBot-DSL 与专家手写实现的可归因实证。

## 1 背景与动机

### 1.1 两个趋势

- **算子编程 AI 化**：成本瓶颈从"人写代码"转为"推理次数、上下文长度、验证成本"。
- **MegaKernel 化**：为压低访存与启动开销，单 kernel 融合的算子数持续上升（昇腾已有 `mega_mla` 类单 kernel 融合样例 `[R-CANNBOT-DSL]`，待复核）。

### 1.2 决策空间的量级

一个 MegaKernel 方案的决策向量 $d=(F,T,B,R,S)$：融合划分 $F$、tiling $T$、buffer $B$、寄存器/VF $R$、同步流水 $S$。

| 对象 | 计数 | 位数（$\log_2$） |
|---|---|---|
| 保序融合划分（$n=100$，相邻边"切/不切"） | $2^{99}$ | 99 |
| 任意分组（允许并行分支） | Bell(100) ≈ $4.8\times10^{115}$ | ≈ 385 |
| 组内参数（50 组 × 4 维 × 5 档） | $5^{200}$ | ≈ 464 |
| 合计上界 | ≈ $2^{560}$ | 560 |

→ 可行解在容量/对齐/依赖约束下会大幅减少，但**仍需实测**（T-1.2）。若实测可行解只有 $10^3$ 量级，本课题动机作废，转做"编译栈自动化质量"研究。

### 1.3 为什么"更强/更贵的 AI"不能直接解决

**(a) 代价不可分解，DP 用不上。** 若融合代价可加（如仅计访存），保序划分的最优可用 $O(n^2)$ 动态规划精确求解——XLA/TVM 的融合策略正是此类。POP 针对的是**不可加**情形：

- UB 容量是**全局共享**资源 ⇒ 各组的可行性互相耦合；
- CV 流水重叠 ⇒ 某组的时延取决于相邻组的排布；
- buffer 复用 ⇒ 代价对划分**非局部**。

不可加性破坏了最优子结构，于是"分成子问题分别最优"不成立。**这是本课题真正的立论基础，而非"数字很大"。** 需要给一个反例：DP 认为最优的方案，实测差 2×（`N-FRAME-PROBLEM §4`）。

**(b) 上下文是硬带宽。** 平铺式做法每次评估要把整段程序装进上下文。程序规模 $\Theta(n)$ 增长，而评估次数需覆盖搜索空间，总成本是两个因子相乘。

**(c) 看全反而更差。** 把与当前决策无关的下层细节塞进上下文，会诱导越层修改，破坏下层自动优化的自由度。

**(d) 散文契约不可执行。** 现有栈的"约束"存在于文档与 skill 描述里，不在可求值的检查器里。后果：

- Agent 无法在下沉前判定可行性，只能试错后由编译失败反推；
- 同一参数在不同文档中口径不一，人/Agent 无法仲裁；
- 无法剪枝（没有可靠的下界），搜索退化为盲试。

> 因此课题的落点不是"再做一个 DSL"，而是"给已有 DSL 补上可执行的契约层"。

### 1.4 目标（可操作化）

在 Ascend 950PR 上，对 ≥3 个真实融合算子：

1. **性能**：达到 AscTile 基线及以上，逼近专家手写（差距 ≤10%，`[待验证]`）；
2. **效率**：等预算（token 与 wall-clock 双口径）下显著优于平铺式 Agent 生成与 best-of-k 随机搜索；
3. **可解释**：每个性能决策能定位到某层契约与某次观测，失败能归因到"契约太松"或"搜索不足"。

## 2 问题定义与研究问题

### 2.1 形式化（严格版见 `N-FRAME-PROBLEM`）

- 层 $L_1\prec L_2\prec L_3$（Tile、Buffer、Register）。
- **契约** $C_k=(\mathcal{V}_k,\Omega_k,\Phi_k,\kappa_k,\mu_k)$：可写变量、可读视图、不变量、代价界、度量。
- **精化** $s_k\sqsubseteq s_{k+1}$：保持上层已定变量，为下层赋值。
- **合法解** $\mathcal{S}$：存在一条精化链且每层 $\Phi_k$ 成立。

### 2.2 研究问题

| RQ | 问题 | 可证伪命题 |
|---|---|---|
| **RQ1 契约** | 五元组能否覆盖 MegaKernel 的性能关键决策？哪些决策无法归层？ | P5 |
| **RQ2 可分离** | 层间耦合（VF↔buffer、融合↔tiling、同步↔流水）在什么条件下可被 assume–guarantee 吸收？ | P5、P6 |
| **RQ3 效率** | 等预算下，可执行契约 + 下沉是否优于平铺、best-of-k、AscTile 直出？ | P4、P10 |
| **RQ4 观测** | 结构化观测是否充分且必要？相比读代码的增益能否测量？ | P7、P9 |
| **RQ5 失败** | 回跳是否可被"失败单调"解释？回跳率能否作为契约质量的诊断指标？ | P6 |

### 2.3 非目标

不替代编译器；不承诺全局最优；不新造 IR（复用 AscTile dialect）；多卡通信融合列为 future work。

## 3 核心思想

### 3.1 与既有三层栈对齐，而不是重造

| POP 层 | 对应既有实现 | POP 增加的东西 |
|---|---|---|
| Tile | `asctile`（`asc.experimental.asctile`） | 融合 grouping 作为**一阶决策变量** + 代价界 |
| Buffer | `ascendc` dialect 的分配/复用 | 可检查的容量/复用契约（而非文档约定） |
| Register | `ascvf`（VF） | VF 边界作为显式决策 + 寄存器压力上界 |

**结论**：POP 的贡献不在"分层"，在"**层的边界可执行**"与"**何时下沉可判定**"。

### 3.2 可执行契约

VISA 2026 的主题句是 *"The virtual ISA is the contract between them"*——虚拟 ISA 是"机器程序员"与"硅"之间的契约面。廖恒在同场报告中把契约推广到嵌套并行计算机的**层间**（`[R-LIAO-VISA]`）。本文把这一形式迁移到算子程序：**每层与层之间也是一份契约**，只是这里的层是抽象层而非并行层。

契约必须能被 checker 求值，而不是被 LLM 读懂：

```python
C_tile = Contract(
    vars   = {fusion_groups, algo_choice},
    views  = {graph, per_group_traffic, capacity_bound},
    phi    = [dep_order(), mem_footprint() <= UB_CAPACITY],
    kappa  = RelativeBound(reference="asctile_default", eps=0.15),
    mu     = ModelLatency(calibrated=True),
)
assert C_tile.check(plan)          # 机器判定，不依赖自然语言
```

三条硬要求：
1. **$\Phi$ 可判定**：给定解，返回值是 {通过, 违反+原因}，不是"建议检查"；
2. **$\kappa$ 可求值**：必须是**下界**（可靠），否则剪枝会剪掉最优（`N-THEORY-REFINE §3`）；
3. **$\Omega$ 可枚举**：视图字段是结构化数据，可被 Agent 程序化读取，也可被人审阅。

### 3.3 观测最小充分性

- **决策可见性**：谁能改哪些变量（$\mathcal{V}_k$）；
- **代价可见性**：谁需要看哪些量才能**排序**候选。

Tile 层不决策 buffer，但融合方案的优劣由 buffer 与同步决定，因此 Tile 层若看不到任何资源信息，排序必然失真。

**修正后的设计**：**决策变量分层，代价模型全局**。
Tile 层不看具体 buffer 分配（$\Omega$ 里没有 buffer 布局），但 $\mu$ 的估计必须包含资源约束的**保守影响**（如"该分组在 UB 容量内最多双缓冲"）。等价地说：**观测的是资源约束，不是资源方案**。

这条区分回答了一个关键问题：Tile 层不做资源决策，凭什么保证排序正确。

### 3.4 下沉判据（可测量）

不下沉/下沉，不由"层数越深越好"决定，而由：

$$\text{gap}_k = \frac{\mu^* - \mu_{\text{best}}}{\mu^*},\qquad \text{headroom}_k = \text{当前层剩余自由度的可达改进上界}$$

**当 $\text{gap}_k > \text{headroom}_k$（剩余自由度解释不了缺口）时才下沉**；否则继续在本层搜索。这个判据把"何时下沉"变成可计算问题（KS2）。

### 3.5 失败单调与冲突定向回跳

- 失败分**结构性**（只依赖已定变量，可永久剪枝）与**偶发性**（依赖未定变量，必须回跳）；
- 分层有效的真正理由：**结构性失败对整棵子树成立**（定理 B）；
- 回跳不是异常，而是"契约不够紧"的信号；**回跳率是契约质量的诊断指标**（推论 B3）；
- 明确声明：不保证完备，不保证全局最优；只保证 soundness 与终止。

### 3.6 混合层次程序

整体 Tile 层表达 + 瓶颈片段下沉 Buffer/Register。边界协议：句柄、生命周期、同步由编译栈插入、不变量全链检查、可无损回退（`N-DESIGN-LAYERED-IR §4`）。

## 6 创新点（与既有工作的精确差异）

| # | 创新点 | vs AscTile | vs CANNBot-DSL | vs MLIR/TVM |
|---|---|---|---|---|
| **C1** | **可执行契约**：$\Phi/\kappa$ 可求值、可剪枝 | AscTile 的同步/分配全自动且**不可协商**，无契约对象 | CANNBot 的契约是 prose skill + 门禁，不可求值 | MLIR 无代价概念；TVM 无层间契约 |
| **C2** | **下沉由空间收缩触发**（gap/headroom 判据） | AscTile 无"何时下沉"的问题（全自动） | CANNBot 靠 Stage 流程与 LLM 判断 | TVM 是固定空间内点搜索，不换变量集 |
| **C3** | **融合 grouping 作为一阶决策 + 代价界反馈** | AscTile/CANNBot 均无法表达 grouping 的搜索空间与代价界 | 同左 | Ansor 的 sketch 不含"融合分组"本身 |
| **C4** | **失败单调理论 + 回跳率诊断** | 无 | 无 | 无 |
| **C5** | **混合层次（整体高层+局部低层）的显式交接协议** | 三层是编译流程，不面向"局部替换" | DSL 单一粒度 | — |

**一句话可证伪主张**（论文标题级）：

> *在 MegaKernel 场景下，把层间契约从散文变为可求值，能使 Agent 在等预算下取得显著更优的解；该收益可归因于契约可剪枝 + 观测结构化，而非模型能力或试错次数。*

> **攻防边界**：C1 是核心。若被质疑"只是把文档写成代码"，只能由 RQ3/RQ4 的对照实验回答：同模型、同预算，散文契约与可执行契约谁更优。

## 7 技术路线与系统架构

```
┌──────────── Agent（策略层）────────────┐
│ 下沉决策 / 预算分配 / 回跳 / 决策日志     │
└──────┬───────────────────────▲────────┘
       │ 工具调用                │ 结构化观测
┌──────▼───────────────────────┴────────┐
│ POP 契约层：Contract 库 + Checker + 代价界 │   ← 本文新增
│  · V/O/Φ/κ/μ 五元组  · 下界剪枝  · 视图导出 │
└──────┬────────────────────────────────┘
       │ 复用，不重造
┌──────▼────────────────────────────────┐
│ AscTile：asctile → ascendc → ascvf     │   ← 既有工业栈
│ （自动同步 / 分配 / 双缓冲 / VF 融合）    │
└──────┬────────────────────────────────┘
       │
┌──────▼────────────────────────────────┐
│ Ascend 950PR 后端（CANN）              │
└───────────────────────────────────────┘
```

**实现策略**：契约层是**旁路（side-car）**——不修改 AscTile 编译器，只在生成前后插入检查与视图；这样可以独立推进，也降低"编译器不配合"的风险。
