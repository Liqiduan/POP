# 契约：可执行、assume–guarantee、可观测

## 1 契约不是"文档里的约束"

A8 的直觉是"每层做部分决策、只看该看的"。本文把它具体化为一个**可求值的对象**：

$$C_k = (\mathcal{V}_k,\ \Omega_k,\ \Phi_k,\ \kappa_k,\ \mu_k)$$

| 元素 | 语义 | 可执行性要求 |
|---|---|---|
| $\mathcal{V}_k$ | 本层可写的自由变量 | 类型化；越界写入直接报错 |
| $\Omega_k$ | 本层可读的结构化视图 | 字段可枚举；不含下层实现细节 |
| $\Phi_k$ | 不变量 | **判定函数**：输入解，输出 {ok, violated(reason)} |
| $\kappa_k$ | 代价界 | **数值下界**（保证不剪掉最优） |
| $\mu_k$ | 度量 | 可计算、可比较、带置信区间 |

**"可执行"是本文对工业现状的核心差异**：CANNBot 的门禁是 prose + LLM 判断；POP 要求 $\Phi/\kappa$ 是代码。判据很简单——**同一输入，两次求值结果必须相同**。

## 2 为什么需要 assume–guarantee

普通"每层一个谓词"的写法在层间耦合下会失败。例如：

- Tile 层选择融合组 ⇒ 决定 UB 上驻留多少张量 ⇒ 决定 Buffer 层可行的 buffer 宽度；
- Tile 层的 tiling ⇒ 决定对齐与连续性 ⇒ 决定 Register 层能否向量化（Register 层对 Tile 层是**偏函数**）；
- Register 层的 VF 融合 ⇒ 改变寄存器压力 ⇒ 反作用于 Buffer 层的最优双缓冲深度。

若每层只检查"自己的谓词"，这些耦合会以编译失败或性能塌陷的形式在最后暴露。

**assume–guarantee 写法**：

$$C_k = (A_k,\ G_k),\qquad A_k \subseteq \bigcup_{j<k} G_j$$

- $G_k$：本层保证（对下层可见的承诺，如"UB 剩余 ≥ 64KB"、"tiling 后 K 维对齐 32"）；
- $A_k$：本层假设（引用上层承诺，如"假定对齐成立"）；
- **非循环性**：$A_k$ 只能引用 $j<k$ 的 $G_j$，因此依赖图天然无环；若下层需要"反作用"（如 VF 压力反作用于 buffer），则通过**收紧上层参数的约束**来表达，而不是直接改上层变量。

**落地形式**：$G_k$ 是一组**可求值的符号上界/下界**（如 `regs_used <= R_max`、`ub_remaining >= 0`），而不是自然语言承诺。

> 这就是"契约层可以旁路于编译器"的技术基础：我们不需要改编译器，只需要在每次生成后**求值这些不等式**。

## 3 观测：决策可见性与代价可见性分离

Tile 层虽不决策 buffer，但融合方案的优劣恰由 buffer 与同步决定；若完全看不见资源，排序必错。

**修正**：

| 概念 | 定义 | Tile 层 | Buffer 层 |
|---|---|---|---|
| **决策可见性** | 能否写该变量 | 不能写 buffer | 能写 buffer |
| **代价可见性** | 能否读该量的**约束**（非方案） | **能**读容量上界、最紧双缓冲深度 | 能读具体分配 |

即：$\Omega_1$ 包含 `capacity_bound`、`min_pipeline_depth` 这类**约束投影**，但不包含 `buffer_layout`。

**这带来一个新的可测问题**：约束投影要多细才够？答案是 §4 的"最小充分性"。

## 4 观测的最小充分性

- **充分**：$\forall s \sim_{\Omega_k} s',\ \arg\max_{v\in\mathcal{V}_k}\mu_k(s[v]) = \arg\max_{v\in\mathcal{V}_k}\mu_k(s'[v])$——看不见的差异不影响本层最优选择。
- **最小**：不存在更粗的视图仍满足充分性。

两种错误：

| 错误 | 症状 | 机制 |
|---|---|---|
| 观测不足 | 决策"看起来对，跑起来差"；换 seed 结论翻转 | 等价类内盲选 |
| 观测过度 | 上层微调下层参数；自动优化失效；上下文膨胀 | 越权观测 → 越层决策 |

A8 的"M3 只观测融合边界"是**主动选择观测边界**，其正确性依赖"资源约束已通过代价可见性补偿"。这不是偷懒，是可检验假设（P9）。

**怎么测**：
1. 静态：构造在 $\Omega_k$ 下不可区分、但下层实现不同的样本对，比较最优 $\mathcal{V}_k$ 决策的一致性率；
2. 动态：记录"上层决策在下层实现变化后是否翻转"的翻转率；
3. 消融：人为增删 $\Omega_k$ 字段，画"解质量 vs 上下文成本"曲线，检验是否存在 U 形最优点（V3）。

## 5 三层契约草案（对齐 AscTile）

### 5.1 Tile 层

| 项 | 内容 |
|---|---|
| $\mathcal{V}_1$ | 融合分组 $F$；每组算法方案 $A$；粗粒度 tile 档位 |
| $\Omega_1$ | 算子图；分组后数据流量；**容量上界与最紧流水深度（约束投影）**；符号化代价 |
| $\Phi_1$ | 依赖序、精度界、单组占用 ≤ 容量、对齐 |
| $\kappa_1$ | 相对 AscTile 默认解的劣化上界 $\epsilon_1$ |
| $\mu_1$ | 代价模型（全局、含资源保守估计） |
| **不观测** | buffer 布局、同步位置、寄存器压力 |

### 5.2 Buffer 层

| 项 | 内容 |
|---|---|
| $\mathcal{V}_2$ | 瓶颈组的 buffer 大小/复用/生命周期、局部展开范围 |
| $\Omega_2$ | buffer 时间线、复用冲突图、容量水位、片上流量 |
| $\Phi_2$ | 容量、别名安全、依赖序、继承 $\Phi_1$ |
| $\kappa_2$ | 相对 Tile 层解的劣化上界 $\epsilon_2$ |
| $\mu_2$ | 实测时延 + 片上流量 |

### 5.3 Register 层

| 项 | 内容 |
|---|---|
| $\mathcal{V}_3$ | VF 边界、向量宽度、展开因子 |
| $\Omega_3$ | VF 分组、依赖链、寄存器压力 |
| $\Phi_3$ | 寄存器上限、对齐、继承 $\Phi_1,\Phi_2$ |
| $\kappa_3$ | 相对 Buffer 层劣化上界 $\epsilon_3$ |
| $\mu_3$ | 实测时延 + 峰值利用率 |

## 6 影响（Influence）：不只是看，还要能改

A8 要求 grouping "人可拖、AI 可交互"。影响接口必须：

- **幂等**：同一操作重复执行结果相同；
- **可撤销**：任意步骤可回退；
- **可序列化**：决策序列是 artifact，可回放、可审阅；
- **有权限**：人 lock > Agent 建议 > 默认；lock 写入 $\Phi$，Agent 必须遵守。
