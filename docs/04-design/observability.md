# 观测与交互：让 Agent 与人不靠"读代码"做决策

**上游**：`N-THEORY-VISA §3`、`N-ARCHIVE-2026-11-24#A8`
**下游**：`N-EXP-PLAN`（RQ4 实验）

> "避免 agent 和人只能通过看代码来观测，对这些是低效而不可靠的。"（`N-ARCHIVE-2026-11-24#A8`）

---

## 1 为什么读代码是坏通道

| 维度 | 读代码 | 结构化视图 |
|---|---|---|
| 带宽 | 一段 200 行的 tile 程序 ≈ 3–5k tokens，其中与当前决策相关的 < 10% | 一个分组视图 ≈ 20 个字段 |
| 信噪比 | 同步/alloc/循环噪声淹没决策信号 | 只呈现该层变量 |
| 可靠性 | 需要"在脑内模拟"执行，易错且不可验证 | 视图由编译器/运行时导出，可复现 |
| 可操作性 | 只能"改文本"，改动语义不明确 | 操作即决策（merge/split/lock），幂等可撤销 |
| 可审阅 | 人难以审阅 Agent 的修改意图 | 决策日志 + 视图 diff |

**但要注意**：结构化视图不是"更少的信息"，而是"**经过选择的信息**"。选择错了比读代码更危险（因为它看起来权威）。所以视图必须能**溯源到 IR**，且支持"下钻"。

## 2 四个视图（对应四类性能关键点）

A8 列出的性能关键点 → 视图映射：

| 性能关键点 | 视图 | 主导层 |
|---|---|---|
| 算子融合边界 | **融合分组图（grouping）** | Tile |
| CV 混合流水、同步 | **Pipeline 时间线（类 chrome trace）** | Tile/Buffer |
| 片上 UB/L1/L0A/B/C 分配与复用 | **Buffer 地址-时间图** | Buffer |
| VF 融合边界 | **VF 依赖图 + 寄存器压力** | Register |

### 2.1 融合分组图

```
┌─────────── MegaKernel Graph ───────────┐
│  [q]──▶(matmul)──▶(softmax)──▶(matmul)──▶[o]
│         └──── group A ────┘   └─ group B ─┘
│  group A: 流量 12MB, 片上占用 78%, 预估 1.9ms  ← 符号代价
│  group B: 流量  4MB, 片上占用 41%, 预估 0.7ms
└────────────────────────────────────────┘
操作：拖拽合并/拆分 · 锁定算法 · 标记"待下沉"
```

**必须显示的量**（否则人/Agent 无法判断）：
- 组内/组间数据流量（融合的核心收益指标）；
- 片上占用率（可行性）；
- 符号化代价估计 + 置信区间；
- 与"不融合"基线的对比差值。

**必须支持的操作**：merge / split / pin algorithm / mark-for-descent / undo。所有操作生成一条**决策记录**（可回放）。

### 2.2 Pipeline 时间线

类 chrome trace：横轴时间、纵轴 core / 流水级；色块 = 计算/搬运/同步；红块 = stall。

```
core0 |==load==|--mm--|==load==|--mm--|
core1 |   |==load==|--mm--|   stall  |   ← 红块：同步等待
              ▲ sync point (可点击 → 显示插入原因)
```

**必须支持**：按 group 过滤、显示 stall 归因（等 buffer / 等同步 / 等数据）、点击跳转到 IR 行。

### 2.3 Buffer 地址-时间图

横轴时间、纵轴片上地址空间；色块 = 各 buffer 的生存期；重叠红色 = 复用冲突；顶部曲线 = 容量水位。

这是 Buffer 层**唯一**能支撑"复用决策"的视图。读代码不可能看出复用冲突。

### 2.4 VF 依赖图

节点 = 向量操作，边 = 依赖；高亮 VF 融合边界；右侧显示寄存器压力曲线。用于判断"再融合一步会不会爆寄存器"。

## 3 反馈通道：cost model + replay

**问题**：真跑一次编译+上板可能要分钟级，搜索需要秒级反馈。

**方案**：
1. **replay**：记录一次真实执行的调度/buffer 决策，改变局部参数后重放，避免全量重编译；
2. **cost model**：用 replay 数据拟合，预测时延/流量/占用；
3. **分层保真度**：Tile 层只需 ±15% 的排序能力（不要求绝对值），Buffer 层需 ±8%，Register 层需 ±5%。

**必须诚实标注不确定性**：每个预测带置信区间；预测与实测偏差超阈值时，视图上明确标红（"此预测不可信"）。否则 Agent 会优化一个幻觉。

> 评测指标：**排序相关性**（Spearman）比绝对误差更重要——搜索只需要"谁更好"，不需要"好多少"。

## 4 Agent 工具接口

观测必须可被 Agent **程序化调用**，而不是只给人看：

| 工具 | 输入 | 输出 |
|---|---|---|
| `list_groups()` | — | 分组列表 + 每组符号代价/占用 |
| `view_group(g)` | group id | 组内算子、边界、流量、可合并候选 |
| `propose_merge(g1,g2)` | 两组 | 合并后的合法性 + 预估收益/风险 |
| `build(variant)` | 决策向量 | 编译产物 + 编译日志 + 合法性报告 |
| `run(variant)` | 产物 | 实测时延/利用率/流量 |
| `replay(variant, patch)` | 变体 + 局部改动 | 预测时延（含置信区间） |
| `trace(variant)` | 产物 | pipeline 时间线数据（结构化） |
| `buffer_map(variant)` | 产物 | 地址-时间数据 |
| `diff(v1,v2)` | 两变体 | 决策差异 + 性能差异归因 |

**设计约束**：所有工具返回**结构化数据**（JSON），而非自然语言描述。自然语言总结由 Agent 自己做，避免"观测被二次转述失真"。

## 5 人机协作

A8 明确"人可以拖动 group，AI 可以交互 group"。这要求同一套视图同时服务人与 Agent：

- **人**：拖拽、锁定、否决；看的是同一份结构化数据；
- **Agent**：通过工具读写同一份数据；
- **冲突解决**：人的锁定（lock）优先于 Agent 的建议，且锁定会写入 contract（$\Phi$），Agent 必须遵守；
- **审阅**：人可以通过决策日志回放 Agent 的每一步，而不必读代码。

**人的角色定位**：人负责**契约边界设定**与**异常裁决**，不负责逐次调参。这也回答了"Agent 团队里人做什么"。

## 6 怎么证明"观测有用"（RQ4 实验）

| 实验 | 设计 | 指标 |
|---|---|---|
| **E-obs-1** | 同模型、同预算：{读代码} vs {读代码+视图} vs {仅视图} | 解质量（利用率）、token、迭代次数 |
| **E-obs-2** | 人对偶：两组工程师分别用两种方式完成同一优化任务 | 完成时间、正确率、主观负荷（NASA-TLX） |
| **E-obs-3** | 观测充分性：人为增删视图字段，测解质量曲线 | 是否存在 U 形最优点（V3） |
| **E-obs-4** | 预测可信度：cost model 偏差 vs Agent 决策失误的相关性 | 相关性 > 0.5 说明"预测误导"是主要失败源 |

> E-obs-1 决定 C1/C3 是否成立：若"看视图"不比"读代码"好，创新点需重新定位。

## 7 风险

| 风险 | 应对 |
|---|---|
| 视图设计与实现工作量巨大（前端） | 先做**文本化结构化视图**（JSON + 简单 TUI），验证有效后再做图形界面 |
| cost model 不准导致 Agent 优化幻觉 | 强制置信区间 + 定期实测校准 + 排序相关性门限 |
| 视图"看起来权威"但选错信息 | 每个字段可溯源到 IR；支持下钻到代码 |
| 人机操作冲突 | lock 机制 + 决策日志 |
