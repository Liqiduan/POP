# 实验方案与评价

**上游**：`N-PROPOSAL §8`、`N-FRAME-PROBLEM §5`、`N-THEORY-REFINE §8`
**状态说明**：本文所有数字为**建议值**，未实测；标 † 者需在 P0 阶段标定。

---

## 0 主张 → 实验 映射（先定这个，再谈细节）

| 主张 | 实验 | 判据 |
|---|---|---|
| (a) 分层在等预算下接近专家 | E0 vs POP-3，8 benchmark | 中位差距 ≤ 10%† |
| (b) 分层压缩上下文与成本 | POP-3 vs E2/E5，token/wall-clock | token 降 ≥ 40%† |
| (c) 结构化观测优于读代码 | A2、A6、E-obs-1 | 解质量与 token 双指标 |
| (d) 单向精化不损失解质量 | A5（关回溯）+ 小规模穷举 | 差距 ≤ 15%† 且完备性可证 |
| (e) 收益来自方法而非模型 | A7（换模型）+ E3（自动搜索） | 换模型后收益不消失 |

> **两个必需的基线**：
> 1. **等预算曲线**：不是只报"最终点"，而是画"性能 vs 预算（token/时间）"曲线，证明 POP 在中低预算段就领先，而非靠预算堆出来；
> 2. **随机搜索基线**：同空间内随机采样 $k$ 个方案取最好（best-of-k）。若 POP 打不过 best-of-k，说明收益来自"多试"而非"分层"——这是最致命的一条，必须正面回应。

## 1 Benchmark（8 项）

| ID | 形态 | 考察决策 | 规模† |
|---|---|---|---|
| B1 | FlashAttention prefill+decode | 融合边界、softmax 数值、VF/CV 流水、UB 复用 | prefill B8·H32·S4096·D128 |
| B2 | MoE GroupGEMM | token 分组、专家 tile 调度、权重驻留 | E64·top8·T8192·H4096·I14336 |
| B3 | GEMM+epilogue | epilogue 融合、tile、Register 级 vector | 4096³ bf16 |
| B4 | Conv-BN-ReLU | 空间 tile、double buffer、CV 流水 | N32·C64·112²·k3 |
| B5 | decode GEMV/MLA | 带宽界、KV 布局、归约 | B64·S8192·kv512 |
| B6 | 长序列 KV（chunked prefill） | 切块、HBM↔UB、跨块流水 | B1·S131072·D128 |
| B7 | 单 block MegaKernel（100+ 步） | grouping、三层耦合 | B8·S2048·H4096 |
| B8 | AllGather+GEMM 重叠 | 跨卡边界、通信/计算流水 | 8 卡·4096² |

**选型理由**：B7 是唯一直接对应"100+ 步"的负载，必须在篇内；B8 是边界（多卡），若时间不够可砍并声明为 future work。

## 2 基线（6 条）

| ID | 基线 | 控制了什么 | 公平性陷阱 |
|---|---|---|---|
| **E0** | 专家手写 Ascend C | 性能上限 | 专家工时与调优轮次**单列**，不折成钱 |
| **E1** | PyAsc asctile 直出 | 编译栈/DSL 表达力 | 默认 tile 未调优，需给同等调优预算 |
| **E2** | 纯 LLM 一次性平铺生成 | 同模型、同 token/$ 上限 | prompt 信息量与 POP 首层对齐 |
| **E3** | 自动调度器/代价模型搜索 | 同编译-运行预算 | 次数 vs 时间口径易被放大 |
| **E4** | TVM/TileLang（若可移植） | 后端差异 | 只作同后端对比，后端差异≠方法差异 |
| **E5** | POP-flat（有观测、单层） | 分离"观测"与"分层" | 与 E2 差异仅在观测 |
| **E6** | best-of-k 随机搜索 | "多试"本身的效果 | 预算必须与 POP 完全对齐 |

E6 回答"是不是只要多跑几次就行"。

## 3 指标

| 维度 | 指标 | 测法 |
|---|---|---|
| 性能 | 峰值算力利用率 % | 以**实测**微基准峰值为分母（不用标称） |
| | 端到端时延 | 20 warmup + 100 iter，中位数 |
| | 有效带宽 | profiler HBM 字节 / 时延 |
| 搜索 | token（in/out）、美元成本 | API usage × 固定价目表快照 |
| | wall-clock、迭代轮数、编译时间 | 日志时间戳（含重试） |
| 质量 | 相对 E0 差距；speedup | 双报，不隐藏 |
| | 跨 seed 分位 | 5 seeds，median 与 P90 |
| 复现 | 环境指纹 | git sha、CANN 版本、seed、机器 SN |
| 人机 | 介入次数、首可用解时间 | 操作者日志 |
| **观测** | 决策一致性、排序相关性 | 见 `N-DESIGN-OBSERVE §6` |

每 run 一行 JSONL，**失败也写**；聚合 CSV + 原始 trace 一并归档（放 `runs/`，不入 git）。

## 4 消融（7 组）

| ID | 去掉什么 | 预期 | 若无变化说明 |
|---|---|---|---|
| A1 | 某层 contract | 空间爆炸/违规上升 | contract 非瓶颈或编译器已代偿 |
| A2 | 结构化观测（退回读代码） | token↑ 质量↓ | 任务过小，观测非必需 |
| A3 | cost model + replay | 轮数↑ 编译时间↑ | 空间窄，廉价代理够用 |
| A4 | 层数降为 2/1 | 先升后平/降 | 层间解耦收益弱 |
| A5 | 关闭回溯 | 若无损则支持 (d) | 退化则单向不成立 |
| A6 | 拆掉 grouping，只留 trace | 融合决策变差 | 图信息冗余 |
| A7 | 换模型 / 换留出 shape | 收益变化但不消失 | 收益来自模型 |

**A5 的记录要求**：除最终值，还要报**回溯触发直方图**（哪一层、什么原因），用于支撑"失败单调 + 冲突回跳"的新表述。

## 5 统计口径

- 每 (bench, baseline) 5 个 LLM seed；时延另做 3 次编译-运行取中位数的中位数；
- 报 median[IQR] 与 P90；以 bench 为配对单位做 Wilcoxon signed-rank，Holm 校正；
- 加速比给 bootstrap 95% CI 与效应量；
- 失败按 ITT 全报，分类（编译错/数值超限/性能回退/预算耗尽），不静默剔除；
- **预测与实测的相关性**（Spearman）单独报告——cost model 的可信度是结论的一部分。

## 6 阶段与 Go/No-Go

| 阶段 | 内容 | 周期† | Go 判据 |
|---|---|---|---|
| **P0 可行性** | B1/B5 × E1/E2 跑通；T-1.1～T-1.5 空间度量 | 2–3 周 | 编译→profiler 链路可复现；可行解 ≥ $10^6$ |
| **P1 单点收益** | B1/B3/B5 × 5 seeds，E2 vs POP-3 | 3–4 周 | ≥2/3 加速 ≥1.15×，token ≤70% |
| **P1.5 理论验证** | $n\le8$ 穷举：S-joint vs S-layer+bt vs S-layer | 1–2 周 | 完备性差距 = 0；单向损失 ≤15% |
| **P2 全量对比** | 8 bench × 7 基线 × 5 seeds | 4–6 周 | ≥6/8 优于 E2；优于 E6；token 降 ≥40% |
| **P3 归因/泛化** | 消融 + 留出 shape + 换模型 | 3–4 周 | 消融方向符合预期；留出差距 ≤10% |

> P1.5 不依赖 950 与大模型，能直接验证定理 A/B，建议提前做。
