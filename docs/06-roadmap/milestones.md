**上游**：`N-PROPOSAL §10`、`N-EXP-PLAN`、`N-FRAME-PROBLEM`

---

## 1 最小可发表单元（MVP）

> **论文甲**：*Executable Contracts for Progressive Operator Programming: 让 Agent 在 MegaKernel 上可判定地下沉*
>
> - 主张：把层间契约从散文变为可求值，能在等预算下显著改善 Agent 的解；
> - 证据：3 个算子（attention / GEMM+epilogue / CV 融合）+ 1 个 MegaKernel case；消融（散文契约 vs 可执行契约）+ 等预算曲线；
> - 不需要：三层全实现、通用 IR、图形前端、多卡。

**先有 MVP，再谈第二篇。**

## 6 写作策略

1. **三张图先行**：决策位数增长图、架构图、等预算曲线。图想清楚，文就成了一半。
2. **主张句开头**：每节第一句是"这一节证明什么"。
3. **诚实即说服力**：主动写"不保证完备""混合编程受栈限制"，比藏起来更可信。
4. **Related Work 按假设组织**：他们假设代价可加/契约可读/空间固定，我们不假设。
5. **Rebuttal 预演**：现在写下最可能的三个质疑与回答（见 §4 风险登记）。
