## A2 · 动机一：复杂度几何增长（原文）

> 随着算子编程走向 AI 化，以及 MegaKernel 的趋势。算子复杂度几何增加，例如融合范围的决策随着算子融合 100+ 计算步骤，膨胀到 100 的组合种。

**解读**：两个趋势叠加——(i) 算子由人写转为 AI 生成；(ii) 单 kernel 融合的步骤数从个位数涨到 100+。二者共同导致"决策空间"（尤其融合范围的划分）从可枚举变为爆炸。

**留痕问题（未改写原文）**："膨胀到 100 的组合种" 表述有歧义，需在 `N-FRAME-PROBLEM` 中给出严格量级（是 2^100、Bell(100)，还是 100 个切分点 × 每点若干选择？）。这是动机能否成立的地基。

## A3 · 动机二：AI 无法对抗指数膨胀（原文）

> AI 极大提升了效率，但是无法对抗几何的数字的膨胀。通过编程方案减少上下文的长度（本质上是减少 AI 的任务和推理），可以提升费用效率，时间效率（AI 可以迭代的更快），以及"实际"可达的最优解（AI 很厉害，但是也无法在 NP 问题中有限时间求解）

**解读**：提出一个**非"更强模型"的解法**——改变问题表征，把"一次性求全局最优"变成"多次求局部可判定问题"。三个收益目标：费用效率、时间效率、实际可达最优性。注意"实际可达"（practically reachable）是有意弱化于"全局最优"的，这是诚实且可辩护的定位。

## A6 · 提案二：Agent 随解空间收缩而逐层下沉（原文）

> 让 agent 随着解空间的变小，选择更底层的 Api 和 IR 进行优化

### A6a · 第一层 Tile：融合边界 + 算法方案

> 在 MegaKernel 第一层：确认融合边界和算子的算法实现方案 - 通过 tile 级 IR + 符号数学。简化 pipeline，内存分配，double buffer，同步这些工作。让编译栈自动的完成。从而 Agent 极大的简化了工作（按传统算子开发，需要做完整的 tiling 内存分配是很繁重的工作），能快速的在解空间尝试大量的方案。找到潜在的最优解。例如 PyAsc 的 asctile 层级编程

**解读**：Tile 层把"繁重但机械"的工作（pipeline 编排、内存分配、double buffer、同步）**卸载给编译栈**，Agent 只负责"有创造性判断价值"的两件事：融合边界、算法方案。关键前提假设：编译栈能从 tile 级 IR 自动生成"可接受"的 pipeline——这是整个提案最大的工程依赖（见 `N-PLAN-ROADMAP` 风险 R1）。

### A6b · 第二层 Buffer：局部展开

> 在最优解上通过将局部展开 Buffer 层进行优化：可以全面的获得硬件能力，同时仍然有 vf 融合等一些自动化的收益，仍然简化了部分任务

**解读**：**局部**展开是关键限定词——不是全程序下沉，只在性能瓶颈处下沉。保留自动化收益（VF 融合）意味着 Buffer 层仍不是裸机编程。

### A6c · 第三层 Register：VF 展开

> 进一步在局部将 register 展开进行优化，如 VF

**编号**：`A6c`。

## A7 · 提案三：多层次混合编程（原文）

> 多层次混合编程：为了实现渐进性，即同时获得在 high-level api 上的简洁计算表达和解空间搜索，又获得 low-level 的全面算子编程能力得到极致性能。程序上会混合 MegaKerenl 作为整体，然后局部同过 buffer/register 进行优化的混合层次编程。

**解读**：这是**"整体高层 + 局部低层"**的异构程序形态。技术难点在于：不同层次的代码如何在同一 kernel 内共存、边界如何传递（buffer 句柄、同步点、生命周期），以及高层部分如何在不被低层污染的情况下继续享受自动优化。

## A8 · 提案四：VISA 与 observation（原文，核心）

> visa 和 oberservation：参考 LiaoHeng 的思路，其实是构造了 Nested 的 VISA 结构，通过 VISA 从上到下的逐步细化，把自动优化的空间逐步缩小通过手动控制极致的优化。而每一层 VISA 上我们都作出部分决策，例如 Tile 上做了融合边界，实现算法的决策，在 buffer 上做了 buffer 大小复用的决策等。这些决策一起形成了一个 nested progressive 的"解"。 对应的，我们在 tile 上只"观测"融合的边界，来留有自动优化的余地（卸载其他的工作到编译器栈给出可接受的解），而不检查内存的分配和具体同步。然后在 buffer 上去"观测"内存的分配等。其实本质是把性能影响的关键问题拆解到每个层次的 IR 进行解决。我们关注：算子融合边界，CV 混合流水，VF 融合边界，同步，片上 UB/L1/L0ABC 的缓存分配等等，对性能关键的影响点。把这些构建到 VISA 的 contract 中，从而可 prgoressive 的进行解。因此这些也必须有"观测"和"影响"的方法，例如 tile 层的融合通过图的"grouping"展示，和人可以拖动的 group，ai 可以交互的 group 进行观测和影响等。对应有 pipeline 类似 chrome trace 的交互，基于 cost model 和 replay 来快速反馈预测性能。buffer 的复用和大小规划。等等，避免 agent 和人"只能"通过看"代码"来观测，对这些是低效而不可靠的。

**拆解出的关键机制**：
- **M1 Nested VISA**：自顶向下细化，逐层缩小自动优化空间（自动优化空间是"被逐步买断"的，而不是一次给完）。
- **M2 每层只做部分决策**：Tile=融合边界/算法；Buffer=大小/复用。决策向量拼成"nested progressive 解"。
- **M3 观测的层级性**：Tile 层**只**观测融合边界，**不**检查内存分配与同步（故意"不看"，以留自动优化余地）；Buffer 层才观测内存分配。
- **M4 性能关键点清单**（应成为 contract 的骨架）：算子融合边界、CV 混合流水、VF 融合边界、同步、片上 UB/L1/L0ABC 缓存分配。
- **M5 观测必须结构化**：graph grouping（人可拖动、AI 可交互）、pipeline（类 chrome trace）、buffer 复用/大小规划视图。
- **M6 反馈闭环**：cost model + replay 快速预测性能。
- **M7 反面动机**：禁止"只能读代码"——低效且不可靠。

**这是全文最原创的一段**：把"自动优化的搜索空间"当作可被逐层**买断（buy out）**的资源，并用"观测边界"而非"代码"来定义每层职责。

## A10 · 提案六：单向性论证（原文）

> 为什么单向的优化方法可行，实际上会遇到，通过 VF 融合，减少了 buffer 的使用，最后导致需要调整 buffer 的分配？这个是对的，但是把问题转化成了一个 loop 从而无法解决。我们可以在形式上认为是单一方向的。例如用 A 表示原始解，B 表示通过 buffer 优化的解，C 表示 tile，B' 表示被 tile 影响后的 buffer 的解，最后达到更优的解 C'，因此从 A->B->C->B'->C'，其实在路径上可以等价到 A->B'->C'. 只是找到这个解的过程，是考虑到了 C 的失败原因，影响到了 A 到 B/B' 的选择过程（即影响了 A 的搜索）。

**解读（必须精确，否则会被审稿人一击致命）**：
- 原文没有说"忽略反馈"，而是说"**把反馈折进搜索信息，而不是折进控制流**"。
- 形式等价的对象是**最终解**（决策向量的取值），不是**搜索路径**，也不是**代价**。
- "单向"是**求解过程的叙事结构**，背后仍是带有限回溯的最佳优先搜索；等价性需要以"可达解集合相同"来陈述，而不是"路径相同"。
- 形式化与证明责任落在 `N-THEORY-REFINE`；这是本课题**最需要严格化**的地方，也是红队重点攻击点。
